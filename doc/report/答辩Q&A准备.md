# 中期答辩 Q&A 准备文档

## 一、整体架构相关

### Q1: 你的网络整体结构是什么？有上采样和下采样吗？

**回答要点：**

整体采用**三尺度渐进式架构**（MultiscaleNet），包含三个处理分支：
- **Small分支**：处理 ¼ 尺度图像（最低分辨率）
- **Mid分支**：处理 ½ 尺度图像
- **Max分支**：处理全尺度图像

每个分支内部是一个**三级U-Net编码器-解码器**结构：

| 层级 | 通道数 | 空间分辨率 | 操作 |
|------|--------|-----------|------|
| Level 1 (Encoder) | dim=48 | H×W | TransformerBlock |
| ↓ **下采样** | — | — | Conv3×3(C→C/2) + PixelUnshuffle(2) |
| Level 2 (Encoder) | dim=96 | H/2×W/2 | TransformerBlock |
| ↓ **下采样** | — | — | Conv3×3(C→C/2) + PixelUnshuffle(2) |
| Level 3 (Bottleneck) | dim=192 | H/4×W/4 | **★MFGCP_TransformerBlock** |
| ↑ **上采样** | — | — | Conv3×3(C→2C) + PixelShuffle(2) |
| Level 2 (Decoder) | dim=96 | H/2×W/2 | TransformerBlock + Skip |
| ↑ **上采样** | — | — | Conv3×3(C→2C) + PixelShuffle(2) |
| Level 1 (Decoder) | dim=48 | H×W | TransformerBlock + Skip |

**跨尺度连接：**
- Small→Mid：`F.interpolate(scale_factor=2)` 双线性上采样
- Mid→Max：`F.interpolate(scale_factor=2)` 双线性上采样
- BFF (Bidirectional Feature Fusion)：跨尺度特征融合（`F.interpolate(scale_factor=0.5)` 下采样后融合）

**INR模块**：对bottleneck特征上采样后，通过隐式神经表示(MLP)连续化恢复图像

### Q2: 为什么用PixelShuffle/PixelUnshuffle而不是转置卷积或池化？

**回答：**
1. **PixelUnshuffle（下采样）**：空间到通道的重排，无信息损失，比Max/Avg Pooling保留更多细节
2. **PixelShuffle（上采样）**：通道到空间的重排，避免转置卷积的**棋盘伪影(checkerboard artifacts)**
3. 这是当前图像恢复领域的主流做法（Restormer CVPR'22、NAFNet ECCV'22、MambaIR NeurIPS'24 均采用）

### Q3: 三个尺度为什么不共享参数？

**回答：**
1. 不同尺度的雨纹形态差异大：¼尺度看到全局雨纹分布，全尺度看到高频细节
2. INR模块通过坐标编码实现连续化表示，已经建立了跨尺度的隐式关联
3. BFF模块提供了显式的跨尺度信息流动
4. 共享参数在消融实验中性能下降（原论文NeRD-Rain CVPR'24的结论）

## 二、创新点1: RFM（残差频域模块）

### Q4: RFM的核心思想是什么？

**回答：**
RFM 在频域对特征进行**幅度谱选择性增强**，同时保持相位信息，最后通过残差连接融合回空域：

```
x_out = x_freq + x_spatial
其中:
  x_freq = Proj(IFFT(σ(W₂·ReLU(W₁·|FFT(x)|)) · e^{j·∠FFT(x)}))
  x_spatial = DWConv3×3(x)  （空域高频残差）
```

### Q5: 为什么对幅度增强而不改相位？

**回答：**
1. **幅度谱 ↔ "what"**：控制图像内容的强度/对比度
2. **相位谱 ↔ "where"**：控制空间结构/边缘位置
3. 雨纹主要表现为特定频率方向的能量叠加（改变幅度），而不改变底层结构（相位）
4. 文献支撑：FocalFrequency Loss (ICCV'21) 和 DeRainMamba (SPL'25) 均验证了幅度增强的有效性
5. 保持原始相位 → 不破坏空间结构 → 避免引入伪影

### Q6: RFM中DWConv的作用是什么？

**回答：**
- FFT是**全局操作**（捕获长距离频率模式），但缺乏局部敏感性
- DWConv3×3是**局部操作**（捕获高频纹理/边缘细节）
- 两者互补：全局频域增强 + 局部空域细节 = 更完整的特征修复

### Q7: RFM放在bottleneck（最深层）的原因？

**回答：**
1. Bottleneck特征分辨率最低(H/4×W/4)，FFT计算复杂度为O(N·logN)，在低分辨率做最高效
2. Bottleneck的感受野最大，频域全局操作与大感受野天然匹配
3. 经验上，低分辨率特征包含更多语义信息，频域增强效果更稳定

## 三、创新点2: MFGCP（频域-梯度协同感知）

### Q8: MFGCP和单独用RFM有什么区别？为什么需要MDPConv？

**回答：**
- **RFM = 频域增强**：全局频率感知，但对方向敏感度不够
- **MDPConv = 方向梯度感知**：五方向微分卷积（水平/垂直/中心/对角/反对角），精确捕获雨纹的方向特征
- **协同设计**：雨纹是定向的线性结构，单纯频域或单纯空域都不够 → MDPConv提供方向先验，RFM提供频率增强，两者互补

MFGCP公式：`y = x + FFN(LN(x)) + RFM(x) + α·MDPConv(x)`

### Q9: α参数是怎么设计的？为什么初始化为0.1？

**回答：**
1. α 是**可学习标量**（`nn.Parameter(torch.tensor(0.1))`）
2. 初始化为0.1（而非0或1）的原因：
   - 0.1 = 小值启动，避免训练初期MDPConv的随机梯度干扰主路径
   - 非零 = 梯度可以回传，α能从训练数据中自适应学习最优融合比例
   - 这是"渐进式引入"的设计哲学（类似Layer Scale in CaiT）
3. 最终α收敛值约0.15-0.25（根据训练日志）

### Q10: MDPConv为什么用Depthwise卷积？

**回答：**
1. **参数效率**：5个方向×每个dim通道 = 如果用普通Conv3×3则参数量是 5×dim²×9，Depthwise只有 5×dim×k²
2. **通道独立**：每个通道独立感知梯度方向，避免通道间信息混淆
3. **最后用1×1 Conv融合**：proj层负责跨通道信息交互

## 四、创新点3: HAFL（分层自适应频域损失）

### Q11: HAFL的动机是什么？

**回答：**
1. 传统L1/L2损失对所有频率一视同仁，但图像恢复的难度**低频 < 中频 < 高频**
2. 如果一开始就强调高频重建，网络容易在低频还没学好时就被高频梯度干扰 → 训练不稳定
3. HAFL引入**课程学习**思想：先让网络学会简单的低频恢复，再逐步引入高频细节约束
4. 类似人类学画画：先画轮廓 → 再画细节 → 最后精修

### Q12: 三个权重的具体调度是怎样的？

**回答：**
```
w_low  = 0.8（恒定，低频全程重要）
w_mid  = 0.5 × min(1, 2t)        → t=0时为0，t=0.5时饱和为0.5
w_high = 0.3 × min(1, max(0, 3(t-1/3))) → t<1/3时为0，t=2/3时饱和为0.3
```

三个阶段：
- **Phase 1 (t=0→1/3)**：只有低频损失主导，网络先学大结构
- **Phase 2 (t=1/3→2/3)**：中频引入，学习纹理和中等细节
- **Phase 3 (t=2/3→1)**：高频精细化，学习边缘和细节

### Q13: warmup_epochs=50 是怎么配合的？

**回答：**
- HAFL有一个额外的线性warmup：前50个epoch从0线性增长到满权重
- 目的：与学习率warmup配合，避免训练早期HAFL过早干扰模型收敛
- 公式：`final_loss = warmup_scale × (w_low×L_low + w_mid×L_mid + w_high×L_high)`

### Q14: 频率划分的cutoff是怎么确定的？

**回答：**
- `cutoff_low = 0.25`，`cutoff_high = 0.75`（归一化频率）
- 这个划分基于图像信号处理经验：
  - [0, 0.25]：全局色调、大面积区域（低频）
  - [0.25, 0.75]：纹理、中等结构（中频）
  - [0.75, 1.0]：边缘、噪声、细微细节（高频）
- 也可以设为可学习参数，但实验中固定值已足够稳定

## 五、总体训练与损失函数

### Q15: 总损失函数是什么？各项权重怎么确定的？

**回答：**
```python
L_total = L_char + 0.01·L_fft + 0.05·L_edge + 0.1·L_l1 + 0.1·L_HAFL
```

| 损失项 | 作用 | 权重 | 来源 |
|--------|------|------|------|
| L_char (Charbonnier) | 像素级重建（鲁棒L1） | 1.0 | 主损失 |
| L_fft | 全频段频域约束 | 0.01 | 辅助频域 |
| L_edge | Sobel边缘保持 | 0.05 | 辅助结构 |
| L_l1 | INR中间尺度监督 | 0.1 | 多尺度监督 |
| **L_HAFL** | ★分层频域课程学习 | 0.1 | **创新点3** |

权重确定方式：网格搜索 + 各损失量级对齐，确保梯度贡献均衡。

### Q16: 消融实验的结果？

**回答（Rain200L数据集）：**

| 配置 | PSNR | SSIM | 增益 |
|------|------|------|------|
| Baseline (NeRD-Rain) | 41.71 | 0.9903 | — |
| + RFM | 41.79 | 0.9906 | +0.08 |
| + RFM + HAFL | 41.89 | 0.9905 | +0.18 |
| + ALL (RFM + MFGCP + HAFL) | **41.93** | **0.9907** | **+0.22** |

- 每个模块递进式贡献正向增益
- 三者叠加不冲突 → 证明设计的正交性

## 六、与现有方法的对比

### Q17: 和Restormer/NAFNet/DRSformer等方法的区别？

**回答：**
| 方法 | 核心特点 | 与本文的区别 |
|------|---------|-------------|
| Restormer (CVPR'22) | 通道注意力Transformer | 无频域增强、无INR |
| NAFNet (ECCV'22) | 简化的非线性激活 | 单尺度、无多尺度INR |
| DRSformer (CVPR'23) | 稀疏Transformer | 无频域-梯度协同 |
| **本文** | **多尺度INR + 频域-梯度协同 + 课程学习损失** | 三者结合的独创性 |

本文独特性：
1. **INR连续表示** → 跨尺度信息的连续化建模（非离散特征拼接）
2. **频域+梯度双路径** → 对雨纹的频率特征和方向特征同时感知
3. **损失层面的课程学习** → 训练策略优化，不增加推理计算量

### Q18: 计算量增加了多少？

**回答：**
- **RFM**：2个1×1Conv + FFT/iFFT + DWConv3×3 → 参数增加约 2×dim² + dim×9 ≈ 70K
- **MDPConv**：5个DWConv + 1×1Proj → 参数增加约 5×dim×k² + dim² ≈ 50K  
- **HAFL**：仅训练时计算，推理时为零额外开销
- **总计**：相比baseline增加约 ~0.5M 参数（<3%），HAFL推理时无额外成本

## 七、可能的刁钻问题

### Q19: "FFT和HAFL都用了频域，是不是重复了？"

**回答：**
完全不同的层次：
- **RFM的FFT = 模型层面**：在网络内部对中间特征做频域增强，是"看得更清楚"
- **HAFL的FFT = 损失层面**：在训练信号上做频率分解加权，是"学得更好"
- 类比：Encoder用Conv提取特征 ≠ 用MSE监督重建，一个是结构设计，一个是优化目标

### Q20: "α初始化为0.1，是不是说MDPConv不太重要？"

**回答：**
不是不重要，而是"渐进式引入"：
- 训练初期FFN+RFM已能提供稳定梯度，MDPConv随机初始化的梯度方向可能有干扰
- 小α让MDPConv有梯度但不主导，随训练推进自适应增长
- 最终收敛值 α≈0.2 说明MDPConv贡献约占20%的梯度幅值 → 并不trivial

### Q21: "如果去掉INR，你的创新点还能工作吗？"

**回答：**
可以。RFM/MFGCP/HAFL 是**模块化设计**，与INR无耦合：
- RFM 作用于U-Net bottleneck的特征 → 可插入任何Encoder-Decoder
- MFGCP 是TransformerBlock的变体 → 可替换任何标准Block
- HAFL 是纯损失函数 → 可用于任何图像恢复网络
- INR是基线NeRD-Rain的特色，我们的创新点是在此基础上**叠加的增强**

### Q22: "为什么不用更先进的频域方法如Wavelet？"

**回答：**
1. FFT vs DWT 各有优势：FFT是全局频率分析，DWT有时频局部性
2. 我们的课题二(MFAMambaIRv2)正是使用了Haar DWT + CascadedFSG
3. 课题一选择FFT的原因：
   - 与INR的连续化表示理念一致（FFT也是连续频率分解）
   - 实现简单高效（PyTorch原生torch.fft）
   - 在图像去雨任务中FFT已被验证有效（DeRainMamba SPL'25）
