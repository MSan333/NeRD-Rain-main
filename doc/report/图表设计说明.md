## 六、DSTA Token 聚合过程可视化

**用途**：课题二创新点3详细阐述处

**元素**：
```
Step 1: Token 密度评估
┌──────────────────────────┐
│ ■■■□■■□□■■■■□□□■        │  (N=256 tokens)
│ 颜色深浅 = 密度分数       │
│ 深色=高密度，浅色=低密度   │
└──────────────────────────┘
        ↓
Step 2: Top-K 选择 (keep_ratio=0.5)
┌──────────────────────────┐
│ ★★★ ★★   ★★★★          │  128个高密度Token → 保留原始KV
│ □□ □□   □□□□ □           │  128个低密度Token → 待聚合
└──────────────────────────┘
        ↓
Step 3: 空间分组聚合 (group_size=4)
┌──────────────────────────┐
│ 保留: [T1][T2]...[T128]  │  128 tokens (原样)
│ 聚合: [G1][G2]...[G32]   │  128/4 = 32 代表tokens
│ 总计: M = 160 tokens      │
└──────────────────────────┘
        ↓
Step 4: 压缩注意力计算
┌────────────────────────────────────┐
│  Q (256) × K^T (160) → Attn (256×160) │
│  计算量: N×M = 256×160 vs N×N = 256×256 │
│  节省: 37.5%                        │
└────────────────────────────────────┘
```

**可视化形式**：
- Step 1 用热力图色块表示每个 Token 的密度
- Step 2 用★和□区分保留和待聚合
- Step 3 用分组括号表示聚合过程
- Step 4 用矩阵大小对比图

## 十、SSDPS 双路径扫描示意图

**用途**：课题二创新点2详细阐述处

**元素**：
```
              输入特征 x [B, HW, C]
                     ↓
            ┌── in_proj + CPE ──┐
            │  [B, HW, hidden]   │
            └────────┬───────────┘
                     ↓
        ┌── torch.split (hidden维度) ──┐
        ↓                               ↓
┌── Path A (语义路径) ──┐    ┌── Path B (空间路径) ──┐
│  [B, HW, hidden/2]    │    │  [B, HW, hidden/2]    │
│                        │    │                        │
│  ① route(x) → cls     │    │  ① 保持光栅顺序       │
│     Gumbel-Softmax     │    │     (无需排序)        │
│                        │    │                        │
│  ② SGN语义排序         │    │  ② 零提示 zero_prompt │
│     按语义相似度重排   │    │     (无ASE)           │
│                        │    │                        │
│  ③ ASE提示注入         │    │  ③ selectiveScan_spa  │
│     prompt = cls×B     │    │     标准SSM扫描       │
│                        │    │                        │
│  ④ selectiveScan_sem   │    │  ④ 直接输出           │
│     语义增强SSM        │    │     空间连续特征      │
│                        │    │                        │
│  ⑤ SGN逆排序           │    │                        │
│     恢复空间顺序       │    │                        │
└──────────┬─────────────┘    └───────────┬────────────┘
           └──── torch.cat (dim=-1) ──────┘
                     ↓
            ┌── out_norm + out_proj ──┐
            │  [B, HW, C]             │
            └─────────────────────────┘
```

**可视化辅助**：
- 配一张对比图展示 SGN 排序 vs 光栅顺序的 token 序列差异
  - 左图：SGN 排序后，语义相似 token 聚集，但空间不连续（天空token远离相邻草地token）
  - 右图：光栅顺序，空间相邻 token 保持连续（局部纹理可通过状态传递建立依赖）
- 配色：语义路径用紫色系，空间路径用青色系
- 标注："语义关联 ← Path A" 和 "空间连续 ← Path B"

**对比图：TSSM（失败）vs SSDPS（新方案）**：
```
TSSM (已弃用):                    SSDPS (新方案):
┌─────────────────┐              ┌─────────────────┐
│ TCE → mod       │              │ 通道分割        │
│ C' = C × mod    │              │ Path A: 语义SSM │
│ ✗ 修改C矩阵    │              │ Path B: 空间SSM │
│ ✗ PSNR↓0.36dB  │              │ ✓ 不改A/B/C/D  │
│ ✗ 破坏协同学习 │              │ ✓ 安全稳定     │
```
