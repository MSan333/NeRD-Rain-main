# H20-141GB 加速训练方案

## 一、硬件对比

| 指标 | RTX 3090 | H20-141GB |
|------|----------|-----------|
| 显存 | 24GB GDDR6X | 141GB HBM3 |
| 有效可用显存 | ~22GB | ~96GB（ECC 保留后） |
| FP16 算力 | 142 TFLOPS | ~148 TFLOPS |
| FP32 算力 | 35.6 TFLOPS | ~60 TFLOPS |
| TF32 算力 | 71 TFLOPS | ~148 TFLOPS |
| 显存带宽 | 936 GB/s | 4.0 TB/s |
| 互联 | PCIe 4.0 | NVLink 900 GB/s |
| 架构 | Ampere (SM86) | Hopper (SM90) |

**H20 核心优势：**
- 显存容量约为 3090 的 **6 倍**，可容纳更大 batch 和更大 patch_size
- 显存带宽约为 3090 的 **4.3 倍**，数据搬运瓶颈大幅降低
- 支持 FP8 / INT8 量化训练（如有需要）
- NVLink 支持多卡高效通信（如扩展多卡训练）

**模型参数量估算：**
- 三尺度网络，每个尺度包含完整的 Encoder-Decoder + TransformerBlock
- max 尺度额外做了 3 轮迭代精炼（encoder_level1_max1/2/3）
- 包含 RFM（频域残差）、MDPConv（多方向微分卷积）、INR（神经隐式表示）、BFU（双向融合）等模块
- dim=48, 总参数量预估约 **30-50M**（较大）

**当前瓶颈分析：**
1. `batch_size=1`：显存利用率极低，梯度噪声大，训练效率差
2. `num_workers=0`：数据加载在主进程，GPU 等待数据
3. 无 AMP：全部 FP32 计算，未利用 Tensor Core
4. 单卡：未利用多 GPU 并行

## 三、课程学习训练策略（核心方案）

### 3.1 策略概述

采用**四阶段课程学习（Curriculum Learning）**，从小到大逐步增加 patch_size：

```
阶段一（极速启动）: patch_size=32,  batch=64, 闪电迭代，学习颜色映射
        ↓ 收敛
阶段二（快速训练）: patch_size=64,  batch=32, 快速迭代，学习基础去雨
        ↓ 收敛
阶段三（加速训练）: patch_size=128, batch=16, 中速迭代，学习局部纹理
        ↓ 收敛
阶段四（标准训练）: patch_size=256, batch=8,  标准分辨率，完整精细化
```

### 3.2 各阶段设计理由

#### 阶段一：patch_size=32

| 项目 | 说明 |
|------|------|
| 计算量 | 仅为 256 的 **1/64**，每个迭代闪电般快 |
| 可用 batch | **64**（显存占用极低，~5-8 GB） |
| 三尺度输入 | max=32×32, mid=16×16, small=8×8 |
| 学习目标 | 快速学到颜色映射、粗略亮度/对比度调整 |
| 收敛速度 | 极快，预计 **100-200 epoch** 即可收敛 |

> patch_size=32 虽然分辨率极低，但模型可以**以闪电般的速度**学到去雨任务最基础的映射关系（亮度校正、颜色映射）。超大 batch（64）提供极稳定的梯度估计，训练初期不发散。

#### 阶段二：patch_size=64

| 项目 | 说明 |
|------|------|
| 计算量 | 为 256 的 **1/16** |
| 可用 batch | **32**（显存 ~10-15 GB） |
| 三尺度输入 | max=64×64, mid=32×32, small=16×16 |
| 学习目标 | 学习基础去雨能力、粗略纹理恢复、初步雨纹识别 |
| 收敛速度 | 很快，预计 **300-400 epoch** |

> 继承阶段一权重后，模型已有基础颜色映射能力，64 分辨率可以快速学到雨纹的基本形态和去除方式。

#### 阶段三：patch_size=128

| 项目 | 说明 |
|------|------|
| 计算量 | 为 256 的 **1/4** |
| 可用 batch | **16**（显存 ~20-30 GB） |
| 三尺度输入 | max=128×128, mid=64×64, small=32×32 |
| 学习目标 | 学习中等尺度的雨纹模式、局部纹理细节、边缘恢复 |
| 收敛速度 | 较快，预计 **800-1000 epoch**（重要过渡阶段） |

> 128 分辨率是效率与精度的最佳平衡点。继承前两阶段权重，模型已具备良好初始化，此阶段完成大部分精度提升。

#### 阶段四：patch_size=256

| 项目 | 说明 |
|------|------|
| 计算量 | 基准（与 3090 原始配置相同） |
| 可用 batch | **8**（显存 ~50-70 GB，H20 充分利用） |
| 三尺度输入 | max=256×256, mid=128×128, small=64×64 |
| 学习目标 | 完整去雨能力，全局上下文建模，高频细节精细化 |
| 收敛速度 | 中等，预计 **800-1200 epoch**（精细化阶段） |

> 这是最终精细化阶段。模型经过前三阶段已具备强大的去雨能力，256 分辨率用于精细化全局上下文和高频细节。由于初始化极好，收敛速度远快于从头训练。

### 3.3 各阶段配置总览

| 阶段 | patch_size | batch_size | start_lr | end_lr | warmup | epoch 数 | 预估每 epoch | 阶段总耗时 |
|------|-----------|-----------|----------|--------|--------|---------|-------------|----------|
| 一 | 32 | 64 | 6.4e-3 | 6.4e-5 | 5 | 200 | ~1s | ~3 分钟 |
| 二 | 64 | 32 | 3.2e-3 | 3.2e-5 | 5 | 400 | ~3s | ~20 分钟 |
| 三 | 128 | 16 | 1.6e-3 | 1.6e-5 | 5 | 1000 | ~32s | ~9 小时 |
| 四 | 256 | 8 | 8e-4 | 8e-6 | 3 | 1400 | ~60s | ~23 小时 |
| **总计** | | | | | | **3000** | | **~33 小时（约 1.4 天）** |

**学习率缩放规则：**

采用**线性缩放**，公式为：

```
new_lr = base_lr × batch_size
       = 1e-4 × N
```

其中 base_lr=1e-4 为 3090 上 batch_size=1 时的原始学习率。

| batch_size | start_lr | end_lr | 说明 |
|-----------|----------|--------|------|
| 1（原始） | 1e-4 | 1e-6 | 基准 |
| 8 | 8e-4 | 8e-6 | 阶段四 |
| 16 | 1.6e-3 | 1.6e-5 | 阶段三 |
| 32 | 3.2e-3 | 3.2e-5 | 阶段二 |
| 64 | 6.4e-3 | 6.4e-5 | 阶段一 |

> batch_size 翻倍，学习率同步翻倍。配合 warmup（每阶段 3-5 epoch）可避免大学习率初期的不稳定性。

> 每阶段切换 patch_size 后重新 warmup。
>
> **对比：** 3090 原始配置（bs=1, ps=256, 无 AMP, 3000 epoch）预估 **300-500 小时（12-20 天）**。
> 四阶段课程学习 + H20 硬件加速，综合加速约 **10-15 倍**。

**每 epoch 时间估算方法：**

- Rain200L 训练集共 200 张图
- 每 epoch 迭代次数 = `ceil(200 / batch_size)`
- 每次迭代耗时 ∝ `patch_size²`（卷积计算量与面积成正比）
- 以阶段四（ps=256, bs=8）为基准：25 次迭代 × ~2.4s/iter ≈ 60s/epoch
- 阶段三（ps=128）：计算量为 256 的 1/4，13 次迭代 × ~2.4s/iter ≈ 32s/epoch
- 阶段二（ps=64）：计算量为 256 的 1/16，7 次迭代 × ~0.4s/iter ≈ 3s/epoch
- 阶段一（ps=32）：计算量为 256 的 1/64，4 次迭代 × ~0.15s/iter ≈ 1s/epoch（含数据加载开销）

**加速来源分解：**

| 加速因素 | 贡献 | 说明 |
|---------|------|------|
| 阶段一~三的小 patch | ~4x | 前 1600 epoch 的平均速度是 256 的 ~4 倍 |
| batch_size 增大 | ~2-3x | 减少 GPU 空闲、提高利用率 |
| AMP 混合精度 | ~1.5-2x | Tensor Core FP16 加速 |
| 数据加载优化 | ~1.2x | num_workers=16 消除加载瓶颈 |

### 3.4 收敛检测与切换策略

**切换条件（满足任一即可切换至下一阶段）：**

1. **PSNR 提升衰减（推荐）：** 连续 N 个 epoch 的 val PSNR 提升低于阈值

| 阶段切换 | 检测窗口 | PSNR 提升阈值 | 说明 |
|---------|---------|-------------|------|
| 一→二 | 10 epoch | < 0.1 dB | 阶段一收敛极快，阈值可大 |
| 二→三 | 15 epoch | < 0.05 dB | 阶段二收敛快 |
| 三→四 | 20 epoch | < 0.02 dB | 阶段三为重要过渡，需充分收敛 |

2. **Loss 变化率：** `(loss_prev - loss_curr) / loss_prev < 0.001`，持续 5-10 个 epoch

3. **固定 epoch 切换（最简单可靠）：**

| 阶段 | 训练 epoch 范围 | 说明 |
|------|----------------|------|
| 一 | epoch 1-200 | 极速启动 |
| 二 | epoch 201-600 | 快速训练 |
| 三 | epoch 601-1600 | 加速训练（重要过渡） |
| 四 | epoch 1601-3000 | 标准精细化 |

> **推荐：** 首次实验使用固定 epoch 切换（简单可靠），后续可根据 PSNR 曲线调整各阶段 epoch 数。

### 3.5 最大 batch_size 确定方法（实操流程）

文档中的 batch_size 为**推荐起始值**，实际最大值需通过以下流程实测确定：

```
Step 1: 设置保守 batch_size（如推荐值的 50%）
  → python train_h20.py --batch_size 32 --patch_size 32 ...

Step 2: 跑 5 个 epoch，监控显存
  → watch -n 1 nvidia-smi
  → 记录峰值显存 peak_mem

Step 3: 估算最大 batch
  → max_batch = floor(batch_size × (96GB × 0.85) / peak_mem)
  → 其中 0.85 为安全系数，预留 ~15GB 给验证和系统

Step 4: 用 max_batch 跑 5 个 epoch 验证
  → 如果 OOM，减 2 重试
  → 如果显存 < 85GB，可适当加 2 再试

Step 5: 确认最终 batch_size，启动完整训练
```

**各阶段推荐 batch_size 范围：**

| 阶段 | patch_size | 推荐 batch | 可探索范围 | 预估显存（推荐值） |
|------|-----------|-----------|-----------|------------------|
| 一 | 32 | 64 | 32-128 | ~5-8 GB |
| 二 | 64 | 32 | 16-64 | ~10-15 GB |
| 三 | 128 | 16 | 8-32 | ~20-30 GB |
| 四 | 256 | 8 | 4-16 | ~50-70 GB |

> **注意：** 增大 batch_size 后需同步调整学习率（按 sqrt 缩放规则）。如果增大 batch 后收敛变慢，说明已超过有效范围，应回退。

### 3.6 阶段切换时的权重继承

模型为**全卷积架构**，权重与 patch_size 无关，可直接继承：

- **模型权重：** 直接加载上一阶段的 `model_best.pth`
- **优化器状态：** Adam 的动量和自适应学习率一并加载，避免重新适应
- **学习率：** 切换后使用新阶段的学习率，并重新 warmup 3-5 个 epoch
- **Scheduler：** 重新初始化 CosineAnnealing，总 epoch 数为本阶段的 epoch 数

## 四、H20 通用加速建议

### 4.1 混合精度训练 (AMP)

当前代码 **未使用 AMP**，这是最直接的加速手段。

在 H20 上启用 AMP（FP16）可获得：
- 训练速度提升约 **1.5-2x**（利用 Tensor Core FP16 加速）
- 显存占用降低约 **30-40%**（FP16 参数 + 激活值）
- 结合 batch_size 增大，综合加速可达 **3-5x**

**AMP 代码修改参考：**

```python
from torch.cuda.amp import autocast, GradScaler
scaler = GradScaler()

# 训练循环
for i, data in enumerate(tqdm(train_loader), 0):
    for param in model_restoration.parameters():
        param.grad = None

    target_ = data[0].cuda()
    input_ = data[1].cuda()

    with autocast():  # 混合精度前向传播
        target = kornia.geometry.transform.build_pyramid(target_, 3)
        restored = model_restoration(input_)

        loss_fft = criterion_fft(restored[0], target[0]) + criterion_fft(restored[1], target[1]) + criterion_fft(restored[2], target[2])
        loss_char = criterion_char(restored[0], target[0]) + criterion_char(restored[1], target[1]) + criterion_char(restored[2], target[2])
        loss_edge = criterion_edge(restored[0], target[0]) + criterion_edge(restored[1], target[1]) + criterion_edge(restored[2], target[2])
        loss_l1 = criterion_L1(restored[3], target[1]) + criterion_L1(restored[5], target[2])
        loss = loss_char + 0.01 * loss_fft + 0.05 * loss_edge + 0.1 * loss_l1

    scaler.scale(loss).backward()
    scaler.step(optimizer)
    scaler.update()
    epoch_loss += loss.item()
```

> **注意：** `torch.fft` 在 AMP 下自动回退 FP32，无需额外处理。CharbonnierLoss 和 EdgeLoss 中的 `.to('cuda:0')` 硬编码建议改为 `.to(input_.device)`。

### 4.3 梯度累积

如果某阶段 batch_size 梯度噪声过大，可使用梯度累积：

```python
accumulation_steps = 4
# 有效 batch = batch_size × accumulation_steps
# 每 4 个 mini-batch 才执行一次 optimizer.step()

for i, data in enumerate(tqdm(train_loader), 0):
    with autocast():
        ...
        loss = loss / accumulation_steps  # 归一化

    scaler.scale(loss).backward()

    if (i + 1) % accumulation_steps == 0:
        scaler.step(optimizer)
        scaler.update()
        for param in model_restoration.parameters():
            param.grad = None
```

### 4.4 编译优化 (torch.compile)

PyTorch 2.0+ 的 `torch.compile()` 图优化，预期加速 **10-30%**：

```python

```

            param.grad = None

        input_ = data[1].cuda()

            target = kornia.geometry.transform.build_pyramid(target_, 3)
            restored = model_restoration(input_)
            loss_fft = criterion_fft(restored[0], target[0]) + ...
            loss_char = criterion_char(restored[0], target[0]) + ...
            loss_edge = criterion_edge(restored[0], target[0]) + ...
            loss_l1 = criterion_L1(restored[3], target[1]) + ...
            loss = loss_char + 0.01 * loss_fft + 0.05 * loss_edge + 0.1 * loss_l1

        scaler.update()

## 九、注意事项

1. **patch_size=32 的下采样兼容性：** 模型做 2 次下采样（PixelUnshuffle），32→16→8，最小特征图为 8×8。Attention 的空间维度为 8×8=64 tokens，计算正常。但需注意 RFM 模块的 FFT 在 8×8 上操作，频率信息较粗，这对初始化影响不大。

2. **patch_size=32 时的小尺度特征：** small 尺度输入仅 8×8，经过 encoder 后特征图较小。但此阶段目标仅为学习基础映射，不需要精细特征，收敛后即可切换。

3. **阶段切换时 warmup：** 每次切换 patch_size 后，务必重新 warmup 3-5 个 epoch，防止学习率跳变导致 loss 震荡。

4. **大 batch 收敛性：** batch_size 增大后梯度更平滑。建议：
   - 观察前 50 个 epoch 的 loss 曲线，确认无发散
   - 如收敛不佳，可尝试梯度累积替代直接增大 batch

5. **显存监控：** 每个阶段开始训练时用 `watch -n 1 nvidia-smi` 监控显存，确认不超过 90GB

6. **权重继承兼容：** 模型为全卷积架构，权重与 patch_size 无关，跨阶段加载无问题。

7. **FFT 兼容性：** RFM 模块的 `torch.fft.fft2/ifft2` 在 AMP 下自动回退 FP32。如遇到 NaN 可对 RFM 模块单独使用 `autocast(enabled=False)`。

8. **先跑短验证：** 每个阶段先用 5-10 个 epoch 验证 loss 正常下降，再启动完整训练。

9. **各阶段 epoch 数可调：** 如果发现某个阶段收敛特别快或慢，可根据 PSNR 曲线动态调整 epoch 数分配。例如阶段一 100 epoch 就收敛了，可将多余的 epoch 分配给阶段三或四。

10. **Rain200L 数据集特性：** 仅 200 张训练图。小 patch 阶段（32/64）由于 patch 小，每张图可提供更多随机裁剪，等效增加了数据多样性，有利于防止过拟合。
